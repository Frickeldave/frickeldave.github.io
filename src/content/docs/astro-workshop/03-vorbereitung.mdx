## Software installieren

### Node.js

Astro benötigt Node.js in aktueller LTS Version.

```bash
# Version prüfen
node --version
npm --version
```

**Installation:**

- **Windows:** [nodejs.org/de/download](https://nodejs.org/de/download/) — Installer herunterladen
- **macOS (Homebrew):** `brew install node`
- **Linux (apt):** `sudo apt-get update && sudo apt-get install -y nodejs npm`

> **Tipp:** Wer mehrere Node.js-Versionen parallel verwalten möchte, nutzt
> [nvm](https://github.com/nvm-sh/nvm) (Linux/macOS) oder
> [nvm-windows](https://github.com/coreybutler/nvm-windows).

Beispiel unter Linux

```bash
cd ~
sudo apt install git curl -y
curl -fsSL https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
export NVM_DIR="$HOME/.nvm"
[ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"  # This loads nvm
[ -s "$NVM_DIR/bash_completion" ] && \. "$NVM_DIR/bash_completion"  # This loads nvm bash_completion
nvm install --lts
nvm use --lts
# Make nvm available in non-interactive login shells (bash -lc)
grep -qF 'NVM_DIR' ~/.profile || printf '\nexport NVM_DIR="$HOME/.nvm"\n[ -s "$NVM_DIR/nvm.sh" ] && \\. "$NVM_DIR/nvm.sh"\n' >> ~/.profile
```

## Starlight-Projekt anlegen

Als Projektbasis dient **Starlight** — das offizielle Astro-Dokumentations-Framework. Es wird
direkt über den Astro-Installer erstellt, kein Fork nötig.

### Schritt 1: Projekt erstellen

```bash
npm create astro@latest -- --template starlight astrows
cd astrows
```

Der Installer stellt ein paar Fragen — empfohlene Antworten:

| Frage | Empfehlung |
|---|---|
|Ok to proceed? (y)|y|
| Install dependencies? | Yes |
| Initialize a new git repository? | Yes |
| TypeScript? | Strict |

### Schritt 2: Dev-Server starten

```bash
npm run dev
```

Die Website ist anschließend unter [http://localhost:4321](http://localhost:4321) erreichbar.

**GitHub Pages: Welcher Repository-Name?**

GitHub Pages unterscheidet zwei Varianten:

| Typ | Repository-Name | URL |
|---|---|---|
| User/Org Page | Muss exakt `USERNAME.github.io` heißen | `https://USERNAME.github.io` |
| Project Page | Beliebig, z.B. `astrows` | `https://USERNAME.github.io/astrows` |

Im Workshop verwenden wir eine **Project Page** mit dem Namen `astrows` — der
User-Page-Slot (`USERNAME.github.io`) ist bei vielen bereits belegt. Bei einer Project Page
muss in `astro.config.mjs` zusätzlich `base: "/astrows/"` gesetzt werden
(siehe [Astro Setup](10-astro-setup)).

### Schritt 3: Repository auf GitHub anlegen und pushen

```bash
# Auf github.com/new ein neues leeres Repository "astrows" mit default Einstellungen anlegen, dann:
git add -A
git commit -m "chore: initial starlight setup"
# Falls "nothing to commit" und noch kein Commit existiert:
# git commit --allow-empty -m "chore: initial commit"
git branch -M main
git remote add origin https://github.com/DEIN-USERNAME/astrows.git
git push -u origin main
```

## Projektstruktur im Überblick

Nach der Installation ergibt sich folgende Struktur:

```
astrows/
├── public/              # Statische Ressourcen (Favicon, robots.txt)
├── src/
│   ├── assets/          # Bilder (werden von Astro optimiert)
│   ├── content/
│   │   └── docs/        # Markdown/MDX-Dokumentationsseiten ← hier arbeiten wir
│   └── content.config.ts # Docs-Collection Schema
├── astro.config.mjs     # Astro + Starlight Konfiguration
├── package.json         # Abhängigkeiten und npm-Scripts
└── tsconfig.json        # TypeScript-Konfiguration
```

Starlight ist bewusst schlank gehalten — keine `components/`, keine `pages/`, keine `styles/`
überladen mit Custom-Code. Neue Dokumentationsseiten entstehen einfach als `.md`- oder
`.mdx`-Dateien in `src/content/docs/`.
