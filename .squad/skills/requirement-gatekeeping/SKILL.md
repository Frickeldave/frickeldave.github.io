# Requirement Gatekeeping

Use before high-impact work on refactors, config, dependencies, deployment, and process changes.

## Workflow

1. Capture requested change and motivation.
2. Draft ticket scope with affected files and acceptance criteria.
3. Get explicit requirement approval from Tony.
4. Implement only within approved scope.

## Sensitive Change Signals

- Refactoring and architecture shifts.
- Package/configuration modifications.
- Deployment workflow changes.
- Systematic content/process changes.

## Validation Checklist

- Issue reference exists.
- Scope matches planned implementation.
- Approval is current and not expired.
- Open questions resolved or explicitly tracked.
